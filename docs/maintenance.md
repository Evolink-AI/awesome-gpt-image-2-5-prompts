# Maintenance

The initial collection contains 250 complete GPT Image 2.5 prompts across seven categories. The collection now includes ten additional complete GPT Image 2.6 prompts; the newest category appears first in README navigation while original case numbers stay unchanged. `data/prompts.json` stores the English metadata and original prompt texts. `data/content-layout.json` defines category routing. The category Markdown files are the readable case collection, and each README links to every case in its language.

Review additions when a contributor supplies a complete public prompt and attributable media. Verify model claims against the source, keep them attributed to the creator, and record external input requirements. Do not infer a prompt from an image or silently repair original syntax. Exclude incomplete or promptless submissions from the prompt catalog. Clearly labelled official showcases may appear separately and must never inflate prompt counts. Preserve the distinction between official examples and creator-attributed results, and between controlled benchmarks and informal comparisons.

For updates, preserve all existing prompt records, case identifiers and attribution. New global case numbers continue after the highest existing number. Keep the historical publication count in dated update entries. `scripts/verify_content.py` independently locks the first 250 records and validates append-only additions, all categories and all locales. Keep `---` separators outside every original prompt block. Update English first, then have each language’s visible text reviewed. Run `python3 scripts/verify_content.py`, check source and media links, and inspect desktop and narrow renderings before publishing. No scheduled update service is configured by this repository.

Use issues for source corrections and removal requests. Record published content changes in `docs/update-log.md`.
